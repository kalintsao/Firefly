# Vite + Vue 3：现代化前端开发的黄金组合

---

## 🚀 为什么选择 Vite + Vue 3？

在 2024 年及以后的前端开发中，**Vite + Vue 3** 已不再是"新选择"，而是**事实上的标准配置**。

| 维度 | Webpack (旧时代) | Vite + Vue 3 (新时代) |
| :--- | :--- | :--- |
| **开发启动** | 分钟级（需打包所有依赖） | **秒级**（利用原生 ESM，按需编译） |
| **热更新 (HMR)** | 随项目增大而变慢 | **始终快速**（仅更新变更模块，与规模无关） |
| **构建工具** | 自身打包 | **Rollup**（产出更优的 Tree-shaking 结果） |
| **Vue 支持** | 需配置复杂 Loader | **原生支持**，开箱即用 |
| **TypeScript** | 需 Babel/esbuild 转译 | **原生支持**，极速类型检查 |

---

## 🛠️ 核心优势解析

### 1. 极致的开发体验 (DX)

Vite 利用浏览器原生 **ES Modules** 特性，开发服务器不再需要打包整个应用。当你启动项目时，Vite 只处理入口文件，其余模块在浏览器请求时按需编译。

- **结果**：无论项目有 10 个页面还是 1000 个页面，启动和 HMR 速度几乎一致。

### 2. Vue 3 的 Composition API + `<script setup>`

Vite 对 Vue 3 的 SFC (Single File Component) 提供了零配置支持，特别是 `<script setup>` 语法糖：

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const count = ref(0)
const double = computed(() => count.value * 2)

function increment() {
  count.value++
}
</script>

<template>
  <button @click="increment">{{ double }}</button>
</template>
```

- **更少的样板代码**：无需 `export default`，无需手动 `return`。
- **更好的类型推导**：TS 类型自动推断，无需额外泛型。
- **更小的打包体积**：编译器自动优化，移除未使用的导入。

### 3. 强大的插件生态

Vite 兼容 Rollup 插件接口，同时拥有自己的原生插件体系：

- `@vitejs/plugin-vue`：Vue 3 SFC 支持
- `unplugin-vue-components`：组件自动导入（告别手动 import）
- `unplugin-auto-import`：API 自动导入（ref, computed 无需引入）
- `vite-plugin-pwa`：PWA 支持

## 🏗️ 最佳实践架构

### 1. 目录结构规范

```text
src/
├── assets/          # 静态资源
├── components/      # 通用组件
├── composables/     # 组合式函数 (Hooks)
├── layouts/         # 布局组件
├── pages/           # 页面视图
├── router/          # 路由配置
├── stores/          # Pinia 状态管理
├── styles/          # 全局样式/变量
├── types/           # TS 类型定义
├── utils/           # 工具函数
├── App.vue
└── main.ts
```

### 2. 状态管理：Pinia

**放弃 Vuex，拥抱 Pinia。** 它是 Vue 官方推荐的新一代状态管理库。

- 完美支持 TS 类型推导
- 模块化设计，无需 `modules` 嵌套
- 支持 SSR 和 Vite 代码分割

### 3. 样式方案

- **UnoCSS / Tailwind CSS**：原子化 CSS，Vite 插件支持极佳，开发时按需生成。
- **SCSS/LESS**：Vite 原生支持，无需额外 Loader。
- **CSS Modules**：通过 `.module.scss` 自动启用作用域隔离。

## ⚡ 性能优化清单

1. **路由懒加载**：`const Home = () => import('@/pages/Home.vue')`
2. **依赖预构建**：Vite 自动使用 esbuild 预构建依赖，无需手动配置。
3. **分包策略**：在 `vite.config.ts` 中配置 `rollupOptions.output.manualChunks`，将 Vue/ElementPlus 等大库单独分包。
4. **图片优化**：使用 `vite-plugin-image-optimizer` 自动压缩。
5. **Gzip/Brotli**：使用 `vite-plugin-compression` 在构建时生成压缩文件。

## 🚧 常见坑与解决方案

| 问题 | 原因 | 解决方案 |
| :--- | :--- | :--- |
| **CJS 依赖报错** | 某些旧库未提供 ESM 格式 | 检查 `optimizeDeps.include` 或寻找 ESM 替代库 |
| **环境变量不生效** | 命名错误 | 必须以 `VITE_` 开头，如 `VITE_API_URL` |
| **TS 路径别名失效** | 配置遗漏 | 需同时配置 `vite.config.ts` 的 `resolve.alias` 和 `tsconfig.json` 的 `paths` |
| **SSR 水合错误** | 客户端/服务端渲染不一致 | 检查 `window/document` 访问，确保在 `onMounted` 中执行 |

## 📝 总结

**Vite + Vue 3** 不仅仅是一个技术栈的选择，更是**开发效率与工程质量的平衡点**。

- **对于新项目**：无脑上，它是当前版本的答案。
- **对于老项目**：如果 Webpack 构建时间已严重影响心情，建议逐步迁移（Vite 提供了官方迁移指南）。

> **一句话建议**：不要在生产环境使用 Vite 的 Dev Server，但请放心在生产构建中使用它，Rollup 的产物足够稳健。
